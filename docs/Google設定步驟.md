# Google 設定步驟（Google 試算表當資料庫）

做完這份設定後，**同仁不需要任何帳號**，用手機掃車上的 QR Code，輸入「登記密碼」就能登記；資料自動存進你的 Google 試算表。
整個設定約 10–15 分鐘，只需要做一次。

## 這個做法怎麼運作

```
同仁的手機 ──→ GitHub Pages 網頁（只有畫面，沒有資料）
                    │  輸入登記密碼
                    ▼
        Google Apps Script（後端，檢查密碼與權限）
                    │
                    ▼
              你的 Google 試算表（資料都在這裡）
```

- **登記密碼**：給同仁，只能「新增」行車紀錄，不能修改或刪除。
- **管理者密碼**：只給管理者，可修改、刪除、管理車輛與名單、備份與還原。
- 試算表裡的「行車紀錄（檢視用）」工作表會自動整理成易讀的表格，可直接查看、篩選、列印。

## 事前準備

- 一個 Google 帳號（建議用公司或單位共用的帳號，不要用私人帳號，以免人員異動時無法接手）。
- 想好兩組密碼：**登記密碼**、**管理者密碼**。各至少 6 個字元，兩組要不一樣，不要用生日、車牌或 123456。

## 步驟

### 1. 建立後端專案

1. 用上面的 Google 帳號登入，打開 <https://script.google.com>。
2. 按左上角「**新專案**」。
3. 點左上角的專案名稱（「未命名的專案」），改成「車輛借用系統後端」。

### 2. 貼上程式

1. 在編輯器裡，把原本的 `function myFunction() { }` **全部刪除**。
2. 打開 <https://github.com/evanchi1111-sys/vehicle-driving-log/blob/main/apps-script/Code.gs>，按右上角的「Copy raw file」複製全部內容，貼到編輯器裡。
3. 找到最上方這兩行，**改成你自己的密碼**（保留單引號）：

```js
var USER_PIN  = 'CHANGE-ME-USER';   // 登記密碼
var ADMIN_PIN = 'CHANGE-ME-ADMIN';  // 管理者密碼
```

   沒有改密碼的話，後端會拒絕運作，這是刻意的保護。
4. 按上方的儲存圖示（或 Ctrl＋S）。

### 3. 建立試算表並授權

1. 在編輯器上方的函式下拉選單選「**setup**」，按「**執行**」。
2. 第一次會要求授權：按「審查權限」→ 選你的 Google 帳號。
3. 會出現「**Google 尚未驗證這個應用程式**」的警告頁，這是因為程式是你自己寫的，請按「**進階**」→「**前往『車輛借用系統後端』（不安全）**」→「**允許**」。
4. 執行完成後，下方「執行記錄」會顯示「試算表已建立：https://docs.google.com/spreadsheets/…」，這就是你的資料庫，可以先存成書籤。

### 4. （建議）檢查後端是否正常

函式選「**selfTest**」→「執行」。執行記錄應顯示類似：

```
{"ping":"admin","set":true,"list":["vehicles","vehicleLogs",...],"delete":true}
```

如果有錯誤訊息，請整段複製給我。

### 5. 部署成網頁應用程式

1. 按右上角「**部署**」→「**新增部署作業**」。
2. 左邊齒輪選「**網頁應用程式**」。
3. 設定：
   - 說明：`v1`
   - 執行身分：**我**
   - 誰可以存取：**所有人**
4. 按「**部署**」，再按一次授權（同上）。
5. 複製「**網頁應用程式網址**」（以 `/exec` 結尾）。

### 6. 把網址交給網頁

把上一步的網址貼給我，我會寫進網頁的設定檔並推送到 GitHub，約 1–2 分鐘後正式網頁就會連到你的試算表。

（想自己做：編輯倉庫的 `config.js`，把 `window.VEHICLE_API = '';` 的單引號中間貼上網址，存檔後等 GitHub 網頁更新。）

### 7. 匯入初始資料

1. 打開網頁，輸入**管理者密碼**登入。
2. 右上角「備份與還原」→「從備份檔還原」→ 選擇初始資料檔（兩台車、使用人名單、往返地點）→「開始還原」。
3. 之後車輛頁的 QR Code：按「列印用 QR Code」，印出標籤貼在車上。

## 日常使用

| 角色 | 做法 |
|---|---|
| 同仁 | 掃車上的 QR Code → 按「返回登記」。若後端把 `USER_PIN` 設成 `''`（空字串）就不需要密碼；有設定登記密碼時，每次開啟網頁要輸入一次 |
| 管理者 | 網頁右上角「管理者登入」（有登記密碼時為「同仁・切換身分」）→ 輸入管理者密碼，即可修改、刪除、維護清單、備份 |
| 查看全部紀錄 | 直接打開 Google 試算表的「行車紀錄（檢視用）」工作表 |

## 每週自動寄送備份（選用）

`Code.gs` 內建每週自動備份：每週一早上 7～8 點，寄一封信給你，附兩個檔案。

| 附件 | 用途 |
|---|---|
| `行車紀錄_日期.csv` | 行車紀錄表格，用 Excel 閱讀、列印、對帳（不能用來還原） |
| `車輛借用系統備份_日期.json` | 完整備份，系統資料損壞時用網頁的「從備份檔還原」匯入 |

設定步驟：

1. 在 Apps Script 編輯器上方的函式選單選 `weeklyBackup`，按「執行」。第一次需要授權（寄信、建立排程），用你自己的帳號允許。
2. 到信箱確認收到「【車輛借用系統】每週備份」，並有兩個附件。
3. 再選 `installWeeklyBackup`，按「執行」一次，每週排程就設好了。到左側「觸發條件」可以看到。
4. 要取消時，執行 `removeWeeklyBackup`。

收件人預設是執行腳本的帳號（也就是你自己）。要寄給其他人，改 `Code.gs` 裡的 `BACKUP_TO`，多個信箱用逗號隔開。備份檔含人員姓名與行車紀錄，收件人越少越好，也請不要轉寄或上傳到公開位置。

## 之後要注意的事

- **改了後端程式**：需要到「部署」→「管理部署作業」→ 鉛筆圖示 → 版本選「新版本」→ 部署，網址不變。
- **更換密碼**：在編輯器改 `USER_PIN` 或 `ADMIN_PIN`，儲存後同上重新部署。更換後同仁會在下一次開啟時被要求重新輸入。
- **密碼錯誤太多會暫時鎖定**：10 分鐘內累計輸入錯誤 30 次，所有人 10 分鐘內都無法登入，之後自動恢復。
- **不要把網頁應用程式網址與密碼公開張貼**，也不要直接編輯試算表裡 `id`、`json` 欄位（會造成資料錯亂）；要改資料請用網頁。「行車紀錄（檢視用）」每次登記後會自動重建，手動改動會被覆蓋。
- **備份**：建議設定上面的「每週自動寄送備份」；也可以用網頁的「備份全部資料」手動下載，或用 Google 雲端硬碟的「建立副本」備份試算表本身。
- **Google 的使用限制**：免費的 Google 帳號有每日執行時間與次數上限，一般公務車登記遠低於上限。
- **資料放在 Google**：行車紀錄含人員姓名，請確認符合單位的資料政策。

## 遇到問題

| 狀況 | 可能原因 |
|---|---|
| 網頁一直顯示「連線中」或「無法連線到資料庫」 | `config.js` 的網址貼錯、部署時「誰可以存取」沒選「所有人」、或網路問題 |
| 輸入正確密碼卻說不正確 | 密碼有空格或大小寫不同；改密碼後沒有重新部署 |
| 顯示「後端尚未設定密碼」 | 程式裡的兩個密碼還是 `CHANGE-ME…` |
| 顯示「密碼錯誤次數過多」 | 被暫時鎖定，等 10 分鐘 |
| 改了程式但沒有生效 | 沒有「新增版本」重新部署 |

## 讓同仁免輸入密碼

把 `Code.gs` 最上方改成：

```js
var USER_PIN  = '';                 // 兩個單引號，中間不放字
var ADMIN_PIN = '你的管理者密碼';
```

儲存後到「部署」→「管理部署作業」→ 鉛筆圖示 → 版本選「新版本」→ 部署（網址不變）。

- 同仁打開網頁就能登記，但仍**只能新增行車紀錄**，不能修改、刪除或看到管理功能。
- 管理者按右上角「管理者登入」輸入管理者密碼。
- **注意**：知道網頁網址的人都能新增行車紀錄與看到駕駛人姓名，網址請只放在車上的 QR Code 與單位內部，不要公開張貼。
